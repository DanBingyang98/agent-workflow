# 向导（Wizard）

**wizard** 是一个 bash 脚本，一步步引导人类走完手动流程——这些流程手做很繁琐，每次向 AI 重新解释也很烦。它打开每个 URL，说明该点什么、复制什么，捕获值，把它们写进该去的地方（`.env`、GitHub secrets），每个阶段都确认，并显示还剩多少。它可能配置第三方服务、运行一次性迁移，或把项目从一个状态搬到另一个状态。

令人愉快的交互体验已经由 [template.sh](template.sh) 解决了——带剩余时间的进度、确认关卡、跨平台打开 URL（含 WSL）、隐藏式秘密输入、幂等的 `.env` upsert、`gh secret`/`gh variable` 写入，以及收尾摘要。**你的工作只是界定流程并编写各阶段。** `STAGES` 标记上方的库在每个 wizard 中完全相同；一致性正是重点——永远不要手工改动它。

wizard 默认是临时的——为一次运行而建，存到 scratch 或 `scripts/` 路径，任务完成即删除。只有当用户想要一条应长期存在于仓库的可重复设置路径时才提交它。

## 流程

### 1. 界定流程

找出人类必须执行的每一个手动步骤，以及沿途捕获的每一个值。先读仓库——不要空手问：

- 设置类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置、`.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是 wizard 必须产出的值）。
- 迁移或转换类：当前状态、目标状态、以及两者之间不可逆的动作。

然后向用户展示按顺序排列的阶段列表和每个阶段产出的值，并确认——他们可以增删或重排。

**完成标准：** 每个阶段都按顺序命名，并且对每个捕获的值你都知道 (a) 人类从哪里获取它，(b) 它写到哪里（`.env`、GitHub secret、两者，或哪里都不写——有些阶段是纯动作），(c) 它是秘密（隐藏输入）还是公开。

### 2. 映射每个阶段的路径

为每个阶段写出人类要走的精确路径：打开哪个 URL、在那里做什么、值显示在哪里、它填充哪个变量——例如「Dashboard → Developers → API keys → Reveal test key → copy」。当你并不确知当前 UI 或确切命令时，明说并问用户或查文档——永远不要编造可能不存在的步骤。

**完成标准：** 每个阶段都能落到陌生人也照做的具体指令。

### 3. 编写向导

把 `template.sh` 复制到目标路径。把示例阶段替换成每步一个 `stage`，按依赖顺序排列。使用库辅助函数——`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`——并把 `TOTAL_STAGES` 和 `TOTAL_MINUTES` 设为诚实的估计（这驱动剩余时间显示）。

守住模板定的标准：在索要值之前先打开 URL，任何秘密都用 `ask_secret`，每个持久化的值都用 `write_env`，`set_secret` 只写给 CI 真正需要的值，任何不可逆动作前都 `confirm`。每个 `stage` 清屏，只显示当前步骤——让一个 stage 只做一件聚焦的事，人类需要看的内容就不会滚出视野。不要碰标记上方的库。

### 4. 验证并交接

- `bash -n <script>`；如果可用就运行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己端到端运行它——它会打开浏览器并阻塞在人工输入上。改为静态追踪：步骤 1 的每个值都被捕获并落到步骤 1 说的地方，每个 `set_secret` 名称与 CI 里的 `secrets.*` 引用完全一致。
- 告诉用户怎么运行。如果它是可重复的设置路径，提交它并从 README 链接，让下一个人直接运行脚本而不是问 AI。
