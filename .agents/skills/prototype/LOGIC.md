# 逻辑原型（Logic Prototype）

一个自包含的单个 HTML 文件——一个**可分享的演示**——让任何人都能通过点击按钮驱动状态模型。当问题关乎**业务逻辑、状态转换或数据结构**时使用——这类东西纸面上看起来合理，只有推到真实用例上才感觉不对。

因为它是单文件、无需安装，你可以交给非开发人员——设计师、PM、领域专家——让他们亲自感受模型。所以它说他们的语言，而不是代码的语言。

## 什么时候是这个形态

- 「我不确定这个状态机能不能处理 X 之后又 Y 的边界情况。」
- 「这个数据模型真的能让我表达……的情况吗？」
- 「写代码之前我想先感受一下 API 应该长什么样。」
- 任何有人想**按按钮、看状态变化**的场景。

如果问题是「应该长什么样」——走错分支了。用 [UI.md](UI.md)。

## 流程

### 1. 写下问题

写代码之前，先写下要原型化的状态模型和要回答的问题。一段话，放在演示顶部（可见的引言，不只是注释）。回答错问题的逻辑原型是纯浪费——把问题写明确，以后无论用户此刻在看还是回来验收，都能核对。

### 2. 把逻辑隔离成可移植模块

把真正的逻辑——回答问题的那部分——放进单个 `<script>` 块，写成一个小型纯模块，以后可以整个搬进真实代码库。页面是临时的；这个模块不是。

正确形态取决于问题：

- **纯 reducer** —— `(state, action) => state`。当动作是离散事件、状态是单个值时好用。
- **状态机** —— 显式的状态和转换。当「现在哪些动作合法」本身就是问题的一部分时好用。
- **一组纯函数**作用于普通数据类型。当没有隐式当前状态——只有变换时好用。
- **有清晰方法面的类或模块**，当逻辑确实拥有持续的内部状态时。

挑最贴合问题的形态，*不是*最方便接页面的那个。保持纯净：没有 DOM、没有 `document`、没有伸手进内部的按钮处理器。页面调用它；反方向没有任何流动。这正是让原型在自身生命周期之后仍有用的东西：问题回答后，验证过的 reducer / 机器 / 函数集自己就搬进真实模块。

### 3. 构建可分享的 HTML 文件

一个文件，纯 HTML/CSS/JS——没有框架、没有打包器、没有服务器，全部内联，双击就能打开、邮件转发也活。任何人都应该能打开即运行。

为非开发人员写。每个标签都用**领域语言**，不是代码——按钮和状态读起来像业务，不像 reducer。用大白话解释正在发生什么。

自上而下用干净的分层布局：

1. **标题和一行说明**——这个演示让你探索什么（第 1 步的问题）。
2. **当前状态**——完整相关状态，渲染成可读面板（带标签的字段，不是原始 JSON 倾倒），每次点击后重渲染，让变化可见。对非开发人员有帮助的地方，点出刚刚变了什么。
3. **自由点击按钮**——每个动作一个按钮，始终可用，任何人都能以任意顺序戳模型。每次点击派发动作并重渲染状态。
4. **引导式演练**——一组**场景（scenarios）**，每个 tab 一个。每个 tab 放一段简短的场景大白话描述——它搭建了什么情境、该看什么——下面是对该场景按顺序要**按的按钮**。每一步都是真实按钮：点击执行该动作并进入下一步。开始演练会重置到已知初始状态，让场景每次跑得一样。

选那些演示棘手用例的场景——快乐路径、刁钻边界、一次本应非法的尝试——就是纸面上难推理的那些。

保持美观但克制：干净的排版、充足间距、一个强调色。不要动画、不要花活——没有任何东西与状态和按钮抢注意力。

### 4. 交付

把文件发给他们，或替他们打开。他们会抽空点演练和自由点击；有趣的时刻是当他们说「等等，这不该可能」或「咦，我本以为 X 会不一样」——那是_想法_里的 bug，这才是全部意义。如果他们想要新动作或新场景，就加。原型会演化。

### 5. 沉淀答案和原型

原型回答完问题后，沉淀答案，然后按 [SKILL](SKILL.md) 描述的方式沉淀原型。逻辑侧的映射：验证过的 reducer / 机器 / 函数集搬进真实模块（决策被吸收）；HTML 外壳搭车进入保留原型的临时分支——作为单个自包含文件，它在那边保持极容易重新运行。

## 反模式

- **不要加测试。** 需要测试的原型不再是原型。
- **不要接真实数据库。** 用内存状态，除非问题专门关于持久化。
- **不要泛化。** 不要「以后要是想支持 X 呢」。原型回答一个问题。
- **不要把逻辑和页面糊在一起。** 如果纯模块引用了 DOM、`document` 或按钮处理器，它就不再可搬移。让页面保持为纯模块上的薄壳。
- **不要上框架、打包器或服务器。** 接收者双击的一个文件；React 应用或 dev server 毁了「可分享」。
- **不要把 HTML 外壳送进生产。** 页面是为手工点击优化过的。它背后的逻辑模块才是值得留下的。
