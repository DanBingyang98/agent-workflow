---
name: grilling
description: 不留情面地拷问用户关于计划、决策或想法。当用户想压力测试自己的思考，或使用任何 'grill' 触发词时使用。
---

持续访谈用户，直到达成共享理解。把它映射成**设计树（design tree）**：每个决策分支成挂在它下面的决策。

按**轮次**工作这棵树。**frontier** 是每个前置条件已定的决策——你现在就能问的问题，不需要猜还没听到的答案。一轮问完整条 frontier：给每个问题编号并给出你的推荐答案。然后等用户回答再进下一轮。

每个问题这样格式：

```
❓ **Q1** - **<question title>**: <question body, might be multiple paragraphs, including multiple choices>

➡️ <your recommended answer>
```

用户每轮的回答重塑这棵树——已定的决策把 frontier 向外推，解锁依赖它们的问题。重算 frontier，问下一轮。答案依赖本轮仍开放问题的那个问题，属于_更晚的_一轮，不是这一轮。

找_事实_是你的活，绝不是用户的。当 frontier 问题需要环境事实（文件系统、工具等）时，派一个子代理去找——不要向用户问任何你自己能查的东西。不要阻塞：进行中的探索是未定的前置条件，所以只有它下游的问题等子代理报告——现在先问 frontier 其余部分。_决策_是用户的——逐个抛给他们，然后等。

frontier 清空时会话完成：设计树每个分支都访问过，没有任何东西被静默假设。在用户确认你已达成共享理解之前，不要行动。
