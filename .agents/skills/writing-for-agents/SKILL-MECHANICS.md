# 技能机制（Skill mechanics）

[`writing-for-agents`](SKILL.md) 的技能专属分支：当文档是技能时什么变了——frontmatter、调用选择、路由器技能。其他一切写作相关都在 `SKILL.md` 的通用参考里。

## 调用

两个选择，交易两种负载：

- **模型可调用** 技能保留 `description`，让 agent 能自主触发它——其他技能也能触及它。你仍能输入它的名字：模型调用总是_包含_用户触及；description 只增加 agent 发现，从不移除人类的。description 是技能的顶层上下文指针，被迫一直保持加载——永久上下文负载换可发现性。内容全是 reference 的模型可调用技能也是共享参考的一个家：另一个技能能调用它，所以几个技能需要的参考住在同一个地方。机制：省略 `disable-model-invocation`，写承载触发分支的面向模型 description（`SKILL.md` 里的指针写作规则完整适用）。
- **用户可调用** 技能把 description 从 agent 的触及范围剥掉：只有人类输入它的名字才能调用，其他技能不能。零上下文负载，但花认知负载——你是必须记住它存在的索引。机制：设 `disable-model-invocation: true`；`description` 变成面向人类的——一行摘要，触发列表剥掉。

只有 agent 必须自己触及技能、或另一个技能必须触及它时，才选模型可调用。如果它只能手动触发，就做成用户可调用，不付上下文负载。

两个用户可调用技能都需要的共享参考不能住在任何一个里——都没有 description，谁都触发不了对方。把它推到技能系统外的普通文件：任何技能都能指向的外部参考。

## 按调用拆分

调用的拆分切法（序列切法在 `SKILL.md` 里）：当你有应该单独触发它的不同 leading word——一个你实际在 prompts 里用的触发词——或另一个技能必须触及它时，拆出模型可调用技能。你为新的常载 description 付上下文负载，所以那个独立触及必须值得。

## 路由器技能

当用户可调用技能多到你记不住，堆积的认知负载由**路由器技能** 治愈：一个用户可调用技能，点名其他技能和何时用每个，让人只需记一个技能。它只能提示，永远不能触发它们：用户可调用技能没有 description，所以除了人类没人能触及它们。
