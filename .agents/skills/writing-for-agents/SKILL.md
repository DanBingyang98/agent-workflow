写任何 agent 消费的文档的参考——技能、`AGENTS.md` / `CLAUDE.md`、被指针到达的文档。包装不同；写作相同：同样的杠杆让每个都可预测——agent 每次运行走同一个_过程_，而不是产出相同输出。

当你写的文档是技能时，读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解 frontmatter、调用选择和路由器技能。

## 上下文指针

**上下文指针（context pointer）** 是 agent 上下文里持有的引用，它命名某些上下文外的材料并编码到达它的条件。技能的 description 是一个；`AGENTS.md` 里命名一份文档的一行是同一个对象。指针的_措辞_，不是目标，决定 agent 何时到达材料——以及多可靠。必须到达的目标后面跟一个措辞弱的指针，是方差 bug：先磨锐措辞，只有磨锐失败才把材料内联。

指针做两份工作——陈述材料是什么，列出应触发到达它的**分支（branches）**（分支是文档处理的不同用例，让不同运行走不同路径）。常载指针的每个词每轮都花钱，所以它比正文更需要修剪：

- **前置引导词** —— 指针是它做触发工作的地方。
- **每分支一个触发词。** 给同一分支换同义词是同一个分支写两遍；合并，只留真正不同的分支。
- **砍掉正文已经承载的身份。**

## 两种负载

你加的每个文档和指针花两个预算之一：

- **上下文负载（Context load）** —— 常载材料对 agent 窗口的成本：`AGENTS.md` 一行、技能 description、任何每轮都坐上下文里的东西，无论触发与否都花 token 和注意力。
- **认知负载（Cognitive load）** —— 对人的成本：存在哪些文档、何时伸手拿每个。人是索引。不是要最小化的成本——它是人类能动性的价格；花在人的判断重要的地方，不需要就移除。

只有通过指针到达的材料以指针自己那一行的价格逃出上下文负载；完全没有指针的材料完全骑在认知负载上。

## 信息层级

文档由两种内容类型构建——**steps（步骤）**（agent 按顺序执行的动作）和 **reference（参考）**（定义、规则、按需查阅的事实）——自由混合：全是 steps（配方）、全是 reference（审查的规则、本技能）、或两者都有。核心决策是每块材料坐在**信息层级**的哪里，一个按 agent 多快需要材料排名的梯子：

1. **In-file step** —— 主层：agent 按顺序做什么。
2. **In-file reference** —— 按需查阅。常常是合法的平级集合（审查的每条规则在同一级）——好安排，不是坏味道。
3. **Disclosed reference（披露的参考）** —— 推出去放在单独文件，由上下文指针到达，只在指针触发时加载。横跨同目录的兄弟文件到完全外部、住在任何地方、任何文档都能指向的参考。

推得太少，顶部臃肿；推得太多，你藏起 agent 真正需要的材料。那个张力就是整个决策。

**渐进披露** 是往梯子下走的动作——出主文件、到位移指针后——让顶部保持可读。主要不是 token 优化：它是层级被保护的方式。分支是最干净的披露测试：内联每个分支都需要的，把只有部分分支触达的推到指针后面。当文档有 steps 时，本该披露的 in-file reference 埋掉它们，把注意它们变成抛硬币——方差杠杆，不只是可读性杠杆。

**共置（co-location）** 是文件内的伴侣：梯子决定一块材料_落多深_，共置决定它落下去后_旁边坐什么_。把概念的定义、规则和注意事项放在一个标题下而不是散落，让读一部分带进邻居。测试：文档应该读起来像写给 agent 的文档——分组材料那样读；散落的不。 （与**重复**不同：重复在一个地方重述一个含义；散落把一个含义碎成许多。）

**臃肿（Sprawl）** 是这里的失败模式：文档就是太长，即使每行都活且唯一。注意力在多余之上变稀，每行多一行要保相关。疗法是梯子：把参考披露到位移指针后，按分支或序列拆分，让每条路径只带它需要的。

## 步骤与完成标准

每个步骤以**完成标准（completion criterion）** 结束——告诉 agent 工作完成的条件。两个属性让它成为杠杆：

- **清晰度（Clarity）** —— agent 能分辨做完没做完吗？含糊的边界（「understanding reached」）招来**过早完成（premature completion）**：在真正完成前结束步骤，注意力滑向_做完_。仍可见的前面步骤——**post-completion steps**——提供拉力；标准的清晰度是阻力。按序防御：**先磨锐边界**（便宜、局部）；只有它不可救药地模糊_并且_你观察到赶工，才通过拆分序列藏起后面的步骤——而且隐藏只在真实上下文边界（交接或子代理派发；内联调用把后面的步骤留在上下文里、什么也没清掉）上有效。
- **要求度（Demand）** —— 它要求多少。「every modified model accounted for」逼出彻底工作，而「produce a change list」不会。要求驱动**legwork（跑腿）**——agent 在工作内做的挖掘，潜伏在措辞里而不是写为自己的步骤——它不受步骤束缚：「every rule applied」绑定一片平铺参考，就像「every step done」绑定序列，这就是全参考文档仍带穷尽杠的方式。

最强的标准既可检查又穷尽。

## 何时拆分

把一个文档拆成两个花两种 load 之一，所以只在切割挣得它时拆：

- **按序列** —— 拆分一段步骤，当 post-completion steps 诱使 agent 赶工眼前的。让它们看不见会在当前任务上驱动更多 legwork。当心反向：合并序列把每个步骤后面的步骤暴露给后面，招来过早完成。
- **按调用** —— 技能专属：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**leading word（引导词）** 是一个已活在模型预训练里的紧凑概念，agent 运行文档时用它思考（_lesson_、_fog of war_、_tracer bullets_）。作为 token 重复，从不作为句子，它累积一个分布式定义，用最少 token 锚定一整片行为，通过征召模型已持有的先验。自己造词如果定义清楚也行，但造词不征召先验——你为定义付的 token 是一个预训练词免费给的；先伸手拿现有词。

它锚定两次。正文里，_执行_：词每次出现 agent 都取同样行为，在平铺参考内部它把注意力聚焦在一类要找的东西上。指针里，_调用_：当同一个词活在你的 prompts、docs 和代码库里，agent 把那套共享语言链接到材料，更可靠地到达它。

猎取用引导词重构的机会。三个地方展开的三元组、花一句指向一个想法的指针——每个都是乞求折叠成单个 token 的段落：

- "fast, deterministic, low-overhead" → _tight_（a _tight_ loop）。
- "a loop you believe in" → _red_ —— 模糊门变成二值可观察状态（loop 在 bug 上 _red_，或不红）。

你赢两次：更少 token，_以及_一个让 agent 挂思考的更锐利钩子。假设每个文档都带着 leading words 会退休的重述——去找它们。

**否定（Negation）** 是这个杠杆旁边的失败模式：用禁止操控把被禁行为拖进上下文、让它_更_可得，不是更不可得。_别想大象_，大象就是全部；否定是强激活概念会压过的弱修饰，所以禁令半读成做那件事的指令。提示**正面**——陈述目标行为（「write one-line comments」），让被禁的永不开口。禁令只在无法正面表述的硬护栏时挣得位置；即便如此也配上正面目标，让注意力落在做什么上。

## 修剪

- 让每个含义保持**单一事实来源（single source of truth）**：一个权威位置，改变行为是一处编辑。**重复（Duplication）** —— 同一含义在不止一个地方——花维护和 token，并把含义在梯子上的显眼程度抬过它真实等级。（引导词是刻意重复 token、绝不重复含义的偶然反例。）
- **环境也是事实来源** —— `package.json` scripts、配置文件、目录布局、`--help` 输出——重述它的文档是**缓存**：一次查找的副本，只在查找贵时挣得它的负载。缓存 agent 找不到的东西：未写下的约定、选择背后的理由、没有配置坦白的坑。留单文件单命令的查找给环境，它们在那里不会过时。
- 逐行检查**相关性（relevance）**：它还影响文档做什么吗？一行因为从不影响任务（纯铺陈，或该披露的分支）或因为随行为/世界变化而过时，失去相关性。更短的文档更容易保相关。没有修剪纪律，默认命运是**沉积（sediment）**：旧层沉淀，因为加安全、删冒险，直到你必须钻穿它们找还活着的。
- 逐句猎**no-ops**：一条模型默认已经遵守的指令，付 load 说废话。测试——它对比默认改变行为吗？——是模型相对的，不是读者相对的：两个人对 no-op 意见不同，是对默认意见不同，靠运行文档解决，不靠辩论。一句失败就删整句，而不是从它里修剪词。测试也分级引导词：太弱打不过默认的词（agent 已经大致彻底时 _be thorough_）是 no-op，修法是更强的词（_relentless_），不是不同技术。
