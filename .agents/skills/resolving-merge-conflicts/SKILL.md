---
name: resolving-merge-conflicts
description: 当需要解决进行中的 git merge/rebase 冲突时使用。
---

1. **查看当前状态**：检查 git 历史与冲突文件。

2. **为每个冲突找到一手来源**：深入理解每处改动为什么发生、原始意图是什么。读提交信息、查 PR、查原始 issues/tickets。

3. **逐 hunk 解决**：尽可能同时保留双方的意图。无法兼容时，选择与合并目标一致的一侧，并注明取舍。**不要**发明新行为。始终解决，绝不 `--abort`。

4. 找出项目的**自动化检查**并运行——通常是类型检查、测试、格式化。修复合并破坏的任何东西。

5. **完成 merge/rebase**：暂存所有内容并提交。如果是 rebase，继续 rebase 流程直到所有提交都完成 rebase。
